# kube_openbao

Deploys a three-member OpenBao cluster using the official Helm chart, integrated
Raft storage, TLS, and one Ceph RBD PVC per member. Audit storage uses separate
RBD PVCs. PVCs are retained when the StatefulSet is deleted or scaled down.

The role reconciles installation, one-time initialization, and seal state. It
initializes only when the OpenBao API reports `initialized=false`, encrypts the
initialization response immediately with SOPS/age, and preserves an encrypted
copy outside the cluster. Later runs are no-ops while members are unsealed and
use the encrypted artifact to unseal members after a restart.

## Required prerequisites

- At least three Kubernetes workers.
- The `ceph-rbd` StorageClass.
- Helm, supplied by the `kube_helm` role.
- SOPS, supplied by the `sops_cli` role on the controller and Ansible control
  machine.
- A CNI that has been tested to enforce Kubernetes NetworkPolicy. Flannel alone
  does not satisfy this requirement.
- A Secret named `openbao-server-tls` in the `openbao` namespace containing
  `tls.crt`, `tls.key`, and `ca.crt`.

The server certificate must validate the configured
`openbao_tls_server_name` and cover the service and StatefulSet peer names. For
the defaults, include at least:

- `openbao`
- `openbao.openbao`
- `openbao.openbao.svc`
- `openbao.openbao.svc.cluster.local`
- `openbao-internal`
- `openbao-internal.openbao.svc`
- `openbao-0.openbao-internal`
- `openbao-1.openbao-internal`
- `openbao-2.openbao-internal`

The private CA key is part of the offline bootstrap and recovery boundary. It
must not be committed to this repository or generated by this role.

Set `openbao_age_recipient` to the public recipient corresponding to the
operator's offline age identity. SOPS discovers the private identity from its
normal configuration or `SOPS_AGE_KEY_FILE` when an unseal is required. The
private identity is never copied to a Kubernetes node.

The role refuses to initialize if an old recovery artifact exists beside an
uninitialized cluster, and refuses to manage an initialized cluster without a
non-empty encrypted off-cluster artifact.

The role verifies Helm but never installs it. The `kube_helm` role owns the
client binary; this role owns only the OpenBao repository, chart values, and
Helm release.

## Client access

Only namespaces carrying the following label may connect to TCP/8200:

```bash
kubectl label namespace <name> security.nebulaiac.io/openbao-client=true
```

OpenBao peer traffic on TCP/8200 and TCP/8201 is restricted to OpenBao server
pods. The servers may also reach cluster DNS and the configured Kubernetes API
service address.
